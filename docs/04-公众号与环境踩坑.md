# 04 公众号与环境踩坑（均为实测）

## 公众号编辑器

| 现象 | 原因 | 对策 | 实测日期 |
|---|---|---|---|
| 橙色信号点粘贴后消失 | 编辑器会删除只含 `&nbsp;`、`font-size:0`、靠背景色显形的空 span | 圆点用 `●` 字符 + `color`（字号 ≈ 点径 ÷ 0.76）；线条用 `border` | 2026-11-13 |
| HTML 做的结尾区：logo 图与外框底色有一圈色差、末尾「见。」被挤到下一行 | 编辑器调整深色背景色；按手机屏宽重新断行 | 整块预渲染成图片 `ending-card.png`，按手机版面 360px ×3 设计 | 2026-11-13 |
| 图片能否随粘贴保留 | — | 预览页把图片内嵌为 base64，点「复制到公众号」后粘贴，图片、logo、圆点全部保留 | 2026-11-13 |
| `<style>`、class、id、div、position、grid 被过滤 | 平台限制 | 全部内联样式；`validate_gzh_html.py` 每次自动检查 | — |
| 文字样式粘贴后丢失 | 文字节点未包 `<span leaf="">` | build_weekly 自动包裹；校验脚本检查 | — |
| 渐变背景可能触发 darkmode 检测弹窗 | 平台检测 | 只用纯色 | — |

## 数据来源

| 现象 | 对策 |
|---|---|
| Drive 连接器导出周报文档报「File too large」（文档常 40MB+） | 从公开的 `https://docs.google.com/document/d/<ID>/mobilebasic` 取正文与图片；需开启链接共享 |
| mobilebasic 图片 URL 默认 `=s800` 缩略 | 改为 `=s0` 取原尺寸（fetch 已处理） |
| 文档图片格式混杂（部分 .png 实为 JPEG、部分 3MB 大 PNG、部分带透明） | process_imgs 统一解码、铺白、缩放、重编码 |
| 作者常见错字：栏目「风险案列」、标题首字母丢失（implicity） | 栏目名在 config 里自动更正；标题人工改并告知 |
| 上传成品到 Drive 失败：「over the 10 MB limit」/「Request payload size exceeds the limit: 10000000 bytes」（连接器单次请求 ≤10,000,000 字节，文件按 base64 计 +33%，即文件须 ≤ 约 7.2MB；2026-11-13 实测） | 图片总预算 5400KB（process_imgs.py），预览页约 6.8MB；build 超 7.2MB 打印 WARNING；上传用文件引用 `sha256:<hash>:<路径>`，不要贴 base64 |
| `update_file` 不能替换文件内容（只改元数据） | 重做同一周：先上传新版，成功后把旧版移入回收站 |

## 渲染环境

| 现象 | 对策 |
|---|---|
| 封面原字体为思源黑体（Noto Sans CJK），macOS 默认没有 | 用苹方 + 调好的字号/字距/描边对齐（墨迹宽高与原图差 ≤2px，数字字形略不同）。若安装了思源黑体，可把 `render_cover.py` 的 `FONT` 换成它并重新调参 |
| 非 macOS 没有苹方 | `FONT` 会退到 Noto Sans CJK SC / 系统无衬线；selftest 第 4 步会提示偏差，按 docs/02 §3 第 3 步重新调参 |
| 约 7MB 的预览页在某些内置浏览器 `file://` 打不开 | 在输出目录起本地静态服务器（`python3 -m http.server`）查看；用户自己的浏览器直接双击即可 |
| 无界面 Chrome 截图尺寸 | 按 CSS 尺寸 × `--force-device-scale-factor`；结尾卡渲染后自动裁掉白边 |

## 已知小事项

- 每日一图如带「[公众号名称]」等占位文字，需作者在原图里改，流程不修改图片内容。
- 封面日期区间按周一至周日自动计算，与文档内容实际覆盖的日期无关。
