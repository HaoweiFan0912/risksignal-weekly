# 02 修改模板

模板 = 文档正文之外、每期固定的部分，全部在 `template/`；样式在 `scripts/build_weekly.py`。

**任何修改后的验收流程**（必须做，在本文件夹下运行）：

```bash
# a. 用示例周生成预览页，浏览器打开目视确认效果（自检会提示与旧标准答案不一致，这是预期的）
python3 scripts/selftest.py --preview

# b. 确认效果是想要的 → 把当前输出存为新的标准答案（含封面参考图），并再次自检
python3 scripts/selftest.py --accept
python3 scripts/selftest.py          # 必须「全部通过」
```

不满意就继续改，不要 `--accept`。

## §1 声明

`template/notice.txt`，**每行一段**，按顺序显示在文末「NOTICE · 声明」区。直接编辑保存，无需出图。

## §2 结尾互动卡

一张图：`template/ending-card.png`（1080px 宽 = 手机版面 360px × 3）。内容：反白 logo + 「如果你觉得这期周报有收获，/ 欢迎**点赞、关注、收藏、转发**，我们下周见。」+ 联系方式。

1. 编辑 `template/ending-card.html`（普通网页，`<br>` 控制换行；版面宽 360px，正文一行最多约 20 个汉字）。
2. 同步改 `template/ending-card-alt.txt`（图片的替代文字，与卡片文案一致）。
3. 出图：`python3 scripts/render_ending_card.py`（无界面 Chrome，自动裁到卡片高度）。
4. 看一眼 `template/ending-card.png`，再走验收流程。

整块做成图片的原因：公众号会改写深色背景色、按屏宽重新断行，HTML 版的 logo 底色与外框会出现色差、末尾两字会被挤到下一行（见 docs/04）。

## §3 封面

封面 = `template/cover-base.png`（无日期底图，1902×827）+ `scripts/render_cover.py` 写入的日期行。

**只改日期写法/字号**：`render_cover.py` 里的 `date_label()`（格式：`2026年11月9日 —11月15日`，破折号前是窄空格 U+2009，跨年写全两个年份）和默认参数 `--size 45 --weight 600 --spacing 4.5 --stroke 1.2`（为匹配原封面思源黑体而调）。

**封面改版（标题/栏目串/图形变了）**：
1. 拿到新封面原图（带一期日期的成品亦可）。
2. 擦掉日期行：对日期所在的横条，逐列用上下干净像素线性插值填充（背景有轻微渐变与噪点，不能用纯色块盖）。参考做法：

   ```python
   from PIL import Image
   im = Image.open("新封面.png").convert("RGB"); px = im.load()
   y0, y1 = 598, 670            # 日期行上方、下方各一条干净的行
   for x in range(95, 760):     # 覆盖日期文字的横向范围
       a, b = px[x, y0], px[x, y1]
       for y in range(y0 + 1, y1):
           t = (y - y0) / (y1 - y0)
           px[x, y] = tuple(round(a[i] * (1 - t) + b[i] * t) for i in range(3))
   im.save("template/cover-base.png")
   ```
3. 量出原日期文字墨迹的左上角，填进 `render_cover.py` 的 `INK_X, INK_Y`；对照原图并排放大，调 `--size/--spacing/--stroke` 使宽高一致（原封面日期墨迹为 599×42px）。
4. 走验收流程（`--preview` 看效果 → `--accept` 同时更新标准答案与封面参考图）。注意示例周的 `配图/公众号/01.jpg` 是旧封面，如需示例也换新封面：`python3 scripts/render_cover.py 2026-11-09 2026-11-15 /tmp/c.png` 后按 1080 宽 JPEG 处理覆盖它，再 `--accept`。

## §4 栏目

- 新栏目或改名：`config.json` → `section_en` 加/改一行（中文名 → 章节标题上的英文标签）。
- 作者常见错字：`section_name_fix`（如 `风险案列 → 风险案例`）。
- 栏目顺序、条数完全跟随文档，无需配置。

## §5 版式与配色

- 规范：`docs/theme-risksignal-outlier.md`（组件库）与 `docs/03-设计规范.md`。
- 实现：`scripts/build_weekly.py` 顶部颜色常量（`INK / SIGNAL / PAPER / BODY / MUTED / SOFT / LINE`）与各组件函数：`label_row`（小标题行）、`daily_chart`、`highlights`（本期看点）、`chapter_head`（栏目标题）、`item`（快讯条目）、`ending`（结尾卡 + 声明）。
- 两处保持一致：改了实现就同步组件库文档。
- 公众号约束：样式全部内联；每个文字节点包 `<span leaf="">`；字号 ≤24px；不用 div/class/id/position/grid；**装饰圆点用 `●` 字符，不用空 span**。改完必须过合规校验（build 与 selftest 会自动跑）。

## §6 位置与环境

`config.local.json`（私密，不提交）：
- `drive` 里的文件夹 ID（项目根、每周文件夹的父文件夹）。Drive 结构变了就改这里，并同步 docs/01 §2。

`config.json`：
- `drive`：周文件夹命名格式、周报文档标题、上传文件名格式。
- `output_root`：输出位置（相对本文件夹或绝对路径）。
- `output_name`：成品文件名。
- `chrome_candidates`：Chrome/Chromium 路径列表，按顺序找第一个存在的。

## §7 图片规格

`scripts/process_imgs.py`：普通配图 → JPEG、宽 1080px；每日一图（信息图）→ PNG、宽 1600px；透明底一律铺白；去元数据。

体积由总预算控制：`TOTAL_BUDGET_KB = 5400`（全部图片合计），扣除 `RESERVE_KB = 700`（每日一图 PNG + 结尾卡）后平均分给每张 JPEG，单张不超过 `MAX_KB = 400`；质量从 88 起逐级下调直到不超过单张上限。预算受 Drive 上传上限约束（预览页 ≤ 约 7.2MB，见 docs/01 §7），**不要调高**；想要更高画质只能减少图片或改为手动上传。
